# Golang 面试题：基础语法与工程常识

这一篇聚焦 Go 面试里最常见的基础题，重点不是背定义，而是把语言特性、运行行为和真实工程场景串起来。

## 1. Go 为什么适合后端开发？

常见回答可以抓住四点：

- 语法简单，协作成本低。
- 并发模型清晰，`goroutine` 和 `channel` 上手快。
- 编译部署方便，单二进制交付很省心。
- 标准库完善，网络、测试、性能分析都有成熟能力。

## 2. `make` 和 `new` 的区别是什么？

- `make` 用于初始化 `slice`、`map`、`channel`。
- `new` 用于分配内存，返回对应类型的指针。

```go
s := make([]int, 3)
m := make(map[string]int)
p := new(int)
```

一句话记忆：`make` 强调“可用的数据结构”，`new` 强调“零值指针”。

## 3. `defer` 的执行顺序怎么答？

`defer` 采用后进先出。它常用于：

- 关闭文件
- 解锁
- 回滚事务
- 统一收尾

如果面试官继续追问，可以补充：`return` 会先确定返回值，再执行 `defer`，最后真正返回。

## 4. `init` 函数有什么特点？

- 包初始化时自动执行。
- 一个文件可以有多个 `init`。
- 依赖包先初始化，当前包后初始化。
- 不建议在 `init` 里塞入过重的业务逻辑。

## 5. Go 是值传递还是引用传递？

更准确的说法是：Go 统一是值传递。

只是有些值本身带有底层地址语义，比如 `slice`、`map`、`channel`、指针，所以看起来像“引用传递”。

## 6. 什么是逃逸分析？

逃逸分析决定变量更可能分配在栈上还是堆上：

- 生命周期短、作用域清晰，通常更容易留在栈上。
- 被外部引用或生命周期变长，更容易逃逸到堆上。

这道题的加分点在于：逃逸到堆上会增加 GC 压力。

## 7. interface 判空为什么经常出坑？

经典例子：

```go
var p *int = nil
var i interface{} = p
fmt.Println(i == nil) // false
```

原因是接口内部同时保存“动态类型”和“动态值”。这里值是 `nil`，但类型不是空，所以整个接口不为 `nil`。

## 速记版

- `make` 初始化内建引用类型。
- `new` 返回零值指针。
- `defer` 后进先出。
- Go 统一是值传递。
- 逃逸分析和 GC 压力密切相关。
