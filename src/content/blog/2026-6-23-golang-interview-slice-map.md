# Golang 面试题：数组、Slice 与 Map

这类题的关键不是背概念，而是能把底层结构、共享行为和并发风险讲清楚。

## 1. 数组和 Slice 的区别

- 数组长度属于类型本身。
- Slice 是对底层数组的一层视图。
- 工程里最常用的是 Slice，不是数组。

## 2. Slice 的底层结构

Slice 可以理解成三元组：

- 指向底层数组的指针
- 当前长度 `len`
- 当前容量 `cap`

## 3. `append` 一定会扩容吗？

不一定：

- 容量足够时，直接复用原数组。
- 容量不够时，申请新数组并拷贝旧数据。

这也是为什么某些 `append` 会影响原切片，某些不会。

## 4. 为什么切片修改会互相影响？

因为多个切片可能共享同一块底层数组。只要修改的是共享区间，就会互相可见。

## 5. `range` 遍历有哪些高频坑？

- 循环变量会被复用。
- 边遍历边修改底层数据，结果可能和预期不同。
- 闭包捕获循环变量时要格外小心。

## 6. map 为什么并发不安全？

map 的内部结构在并发写入时可能被破坏，所以：

- 读写并发不安全。
- 写写并发也不安全。
- 常见解决方案是 `map + 锁`、`sync.Map`、分片锁。

## 7. nil Slice 和空 Slice 怎么区分？

- 两者长度都可以是 0。
- `nil` Slice 判空为真。
- 空 Slice 判空为假。

这类差异常见于 JSON 编码和接口返回值约定。

## 速记版

- 数组长度属于类型，Slice 是动态视图。
- Slice 共享底层数组时，修改会互相影响。
- `append` 可能扩容，也可能复用原数组。
- map 平均查询快，但并发读写不安全。
